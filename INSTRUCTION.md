N.B.: Ось посилання на репозиторій з результатами моєї важкої роботи: 
https://hub.docker.com/r/leoleiden/todoapp/tags

Завадання передбачає докерізацію веб-застосунку Django ToDo-List, що вже має базовий функціонал, включаючи систему облікових записів, API та користувацький інтерфейс. Для реалізації фронт-енду використовуються CSS (Skeleton) та JavaScript (jQuery). Метою завдання було не лише досягнення тестового запуску додатку,  але і його пакування в Docker-образ і підготовці до розгортання, а також документуванні усього процесу. До ключових етапів належали  встановлення залежностей, міграцію баз даних, запуск сервера на визначеному порту (0.0.0.0:8080), збірку Docker-образу, його публікування  в особистому репозиторії Docker-Hub, і, відповідно, створення детального файлу INSTRUCTION.md з інструктажем щодо минулих дій. 

Для успішного виконання цього завдання необхідні:
- Python 3.8, а також Django;
- Notepad++ чи Visual Studio Code для написання власне самого Dockerfile і не тільки;
- Docker Desktop (або Docker Engine, але не обидва, інакше можливий конфлікт програмного забезпечення) - необхідні для збірки та запуску контейнерів;
- Docker Hub + аккаунт: Потрібен для публікації створеного образу;
- Git + аккаунт: Використовується для контролю версій та створення Pull Request з залитим туди інструктажем.

## 1.Клонування репозиторію.
Отримано локальну копію проекту Django ToDo List з GitHub.
git clone https://github.com/leoleiden/devops_todolist.git
cd devops_todolist

## 2.Виправлення settings.py
Виявлено та виправлено помилку django.core.exc/eptions.ImproperlyConfigured, яка виникала під час виконання collectstatic.
Зміни: Додано рядок STATIC_ROOT = os.path.join(BASE_DIR, 'staticfiles') до файлу todolist/settings.py. Це вказує Django, куди збирати статичні файли під час підготовки образу. Пересвідчено, що import os присутній у файлі settings.py.

## 3. Створення та редагування файлу Dockerfile
(нижче - відкоментований зміст Dockerfile)

# Використовуємо багатоетапну збірку для оптимізації розміру фінального образу.
Цей етап встановлює залежності та виконує міграції.
ARG PYTHON_VERSION=3.9
FROM python:${PYTHON_VERSION}-slim-buster AS builder
# Встановлюємо робочу директорію всередині контейнера
WORKDIR /app
# Копіюємо файл requirements.txt
COPY requirements.txt .
# Створюємо віртуальне середовище та встановлюємо залежності в нього.
# Це гарантує, що всі пакети знаходяться в одному, відомому місці (/venv).
RUN python -m venv /venv && \
    /venv/bin/pip install --no-cache-dir --upgrade pip && \
    /venv/bin/pip install --no-cache-dir -r requirements.txt
# Копіюємо решту коду програми
COPY . .
# Виконуємо міграції бази даних та збираємо статичні файли,
# використовуючи Python з віртуального середовища.
RUN /venv/bin/python manage.py migrate
RUN /venv/bin/python manage.py collectstatic --noinput
# Етап виконання (Runner Stage)
# Цей етап створює мінімальний образ для запуску програми.
FROM python:${PYTHON_VERSION}-slim-buster AS runner
# Встановлюємо змінну середовища для оптимізації виведення логів Python у Docker.
ENV PYTHONUNBUFFERED=1
# Копіюємо віртуальне середовище з етапу builder.
# Це гарантує, що всі залежності доступні.
COPY --from=builder /venv /venv
# Встановлюємо робочу директорію для програми
WORKDIR /app
# Копіюємо тільки код програми з етапу builder
COPY --from=builder /app /app
# Відкриваємо порт, який буде слухати Django сервер
EXPOSE 8080
# Команда, яка буде виконуватися при запуску контейнера
# Використовуємо Python з віртуального середовища.
CMD ["/venv/bin/python", "manage.py", "runserver", "0.0.0.0:8080"]

## 4. Виконання команди збирання: У кореневому каталозі проекту 
#(devops_todolist), де знаходиться новостворений Dockerfile, запускаємо команду для збирання образу.
docker build -t todoapp
#-t todoapp: Присвоює зібраному образу назву todoapp.
#.: Вказує Docker використовувати Dockerfile у поточному каталозі.

## 5. Запуск контейнера
docker run -d -p 80:8080 todoapp
#-d: Запускає контейнер у фоновому режимі (detached mode), звільняючи термінал.
#-p 80:8080: Мапує порт 80 хост-машини (ззовні) на порт 8080 всередині контейнера (де працює Django).

## 6. Перевірка роботи застосунку
Дія: Відкрийте ваш веб-браузер і введіть одну з наступних адрес:
Адреси:
http://localhost/
http://127.0.0.1/
Очікуваний результат: Ви повинні побачити інтерфейс вашого Django ToDo List застосунку. Це підтверджує, що контейнер успішно запущений і застосунок доступний.

## 7, Підготовка Git та створення Pull Request (PR)
**Дія:** Зафіксуйте всі зміни у Git та створіть Pull Request.
**Команди:**
1.  **Додайте новий файл до Git:**
    ```bash
    git add INSTRUCTION.md
    ```
2.  **Зафіксуйте зміни:**
    ```bash
    git commit -m "Додано Dockerfile, виправлено settings.py та додано INSTRUCTION.md"
    ```
3.  **Відправте зміни до вашого форку на GitHub:**
    ```bash
    git push origin main # або назва вашої робочої гілки
    ```
4.  **Створіть Pull Request:**
    Перейдіть на сторінку вашого форкнутого репозиторію на GitHub. Там ви повинні побачити опцію для створення Pull Request з вашої гілки до оригінального репозиторію.
